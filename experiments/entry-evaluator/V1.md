# V1: Forebody heat distribution and numerical verification

## Scope

This change answers two bounded questions: how the existing stagnation heat-flux history maps to an assumed finite surface, and whether the current coolant ranking is stable under time-step and angular-grid refinement. The distribution is an explicit sensitivity assumption, not a calibrated hypersonic heating correlation.

No new rarefied heating, chemistry, trajectory physics or system-mass iteration is introduced. Existing limitations still apply, including the radiative correlation's reported validity envelope.

## Model

For convection and incident radiation separately:

```text
q_conv(theta,t) = q_conv_stag(t) * cos(theta)^n_conv
q_rad(theta,t)  = q_rad_stag(t)  * cos(theta)^n_rad
Q_vehicle(t)   = sum_i A_i * (q_conv_i(t) + q_rad_i(t))
```

The angular measure is `dA = A_total * sin(theta) dtheta / (1-cos(theta_max))`. Equal intervals in `mu=cos(theta)` define equal-area rings. The code integrates each power-law profile analytically within a ring; it does not approximate its incident power by a point sample. For a hemisphere, the average profile factor is `1/(n+1)`. Uniform heating is a separate control with factor 1.

`coolant.cooled_area_m2` is the total actual area represented by this surrogate. It is not the aerodynamic projected area, `vehicle.reference_area_m2`. Existing 12 m2 is retained as an input assumption. `vehicle.nose_radius_m` remains the radius used in stagnation correlations and Knudsen number. The normalized angular model does not reconstruct the real shape from that radius. For an actual spherical cap these quantities must satisfy `A=2*pi*R^2*(1-cos(theta_max))`; the current 12 m2 / Rn=1 m example is not such a spherical cap. Replace the area weights/profile with geometry or reference data before making an absolute vehicle-mass claim.

Example configuration:

```yaml
surface:
  model: cosine_cap
  theta_max_deg: 90.0
  zones: 32
  convective_exponent: 1.0
  radiative_exponent: 1.0
```

The two exponents can differ. Sharing them in the default sensitivity study is a transparent simplification, not a claim that incident radiation follows convective heating. Set `surface.model: uniform` for a control using the old area treatment. A missing section also selects uniform behavior for compatibility.

## Why independent wall zones matter

Each ring retains its own temperature, thermal storage, reradiation and cooling request:

```text
C_areal * dT_i/dt = q_in_i - q_reradiated_i - q_backface_i - q_coolant_i
mdot_total = sum_i A_i * q_coolant_i / delta_h_i
```

Cooling starts locally when that ring would otherwise exceed the configured setpoint. Multiplying the old coolant mass by an average heating factor would incorrectly scale the wall's stored energy and reradiation too. Tests include an analytic threshold case that distinguishes these implementations.

A separate stagnation probe always sees the full incident stagnation flux. It has zero integration area and therefore adds no coolant mass, but still enforces the local thermal/coolant feasibility check. `peak_wall_temperature_k` covers the probe and all rings. The summary's `peak_heat_flux_w_m2` and `heat_load_mj_m2` retain their **stagnation** meaning. Integrated power/energy use the new `vehicle_*` fields. The local maximum must not be replaced with a surface average.

V1 retains the V0 surface-pressure estimate at all rings. It does not add pressure distribution, lateral conduction, finite pump flow or imperfect wall-fluid heat transfer. These constraints are not inferred from a successful numerical test.

CoolProp uses a reusable HEOS state and an exact, bounded state cache. The V0 rounded cache reused whichever state entered a temperature/pressure bin first, making enthalpy slightly dependent on the time grid and visit order. Tests compare the new calculation against `PropsSI`; small differences from old V0 values are expected. See [CoolProp's low-level interface](https://coolprop.org/coolprop/LowLevelAPI.html).

## Run the verification study

From `experiments/entry-evaluator` with the existing environment active:

```bash
python -m unittest discover -s tests -v
python run_convergence.py --workers 16 --output-dir convergence-v1
```

The runner reads `convergence.yaml`, reuses the four fluid definitions in `batch.yaml`, and deliberately ignores `batch.matrix`. It fixes entry at 200 km, 15 km/s, -11 degrees and runs:

- dt = 0.1, 0.05, 0.025, 0.0125 s;
- uniform control and broad/nominal/narrow angular profiles (exponents 0.5, 1, 2);
- 32 rings for each cosine case;
- an additional 64-ring run at the finest dt for each cosine case (uniform repeats as a control).

Total: 80 independent simulations. The default process count is 4; use `--workers` to fit the machine. Use a new output directory each time; the runner refuses to overwrite a previous study. It does not save full trajectories for this study. `run_entry.py` and `run_batch.py --history` remain available for time histories.

Outputs:

| File | Meaning |
| --- | --- |
| `manifest.json` | All exact case configurations, source SHA-256 hashes, Git revision and dependency versions |
| `run-*.json` | Individual results, saved as each finishes |
| `all_runs.csv` | All numerical observations |
| `convergence_report.json` | Adjacent dt comparisons, 32/64-ring comparisons and pairwise ranking stability |
| `ranking.csv` | Finest-step, refined-grid results for each surface profile; ratios against matched water runs |

The report returns exit code 0 only when the numerical and ranking gates both pass. Failure/skip/max-time runs cannot become successful zero-mass entries. This benchmark requires `terminal_velocity`; reaching the altitude limit first does not pass its gate. This is not the later full trajectory classification/sweep.

## Acceptance criteria

All adjacent dt pairs, not just the finest pair, and the final angular refinement must agree within `atol + rtol*abs(reference)`:

| Observable | Relative tolerance | Absolute floor |
| --- | ---: | ---: |
| Consumed coolant | 1% | 0.01 kg |
| Peak stagnation heat flux | 1% | 1 W/m2 |
| Minimum altitude | 0.1% | 0.01 km |
| Peak dynamic pressure | 1% | 1 Pa |
| Peak wall temperature | 0 | 0.5 K |
| Peak coolant flow | 1% | 0.01 kg/s |
| Integrated incident heat | 1% | 0.001 MJ |

These are chosen numerical criteria, not physical uncertainty bounds. Pairwise rankings must retain the same strict ordering over every tested dt/profile/grid. Differences within 1% plus 0.01 kg are marked unresolved. Any tie, reversal or unavailable result prevents a strict ranking-stability pass. Absolute masses may differ strongly between profiles even when ranking stays stable.

Trajectory integration is RK4, but wall updates and heat/mass accumulation retain the V0 explicit time treatment. Terminal events are still detected at step boundaries. Consequently this is an empirical refinement check, not a claim of fourth-order convergence for coolant mass or event time. A last step is clipped at max_time. The history labels start time and step-end time explicitly; thermal and consumed-mass fields describe the step end while atmosphere/trajectory fields describe the start.

The integrated absolute wall-balance residual is reported as a diagnostic and tested against analytic manufactured cases. It checks consistency of the equations being implemented, not the correctness of the physical closures.

## Recorded verification run

The [checked-in verification record](verification-v1.json) contains the tested source hashes, dependency versions, input configurations, maximum comparison errors and finest-grid results. All 80 simulations reached the velocity terminal condition. All configured numerical comparisons and all six pairwise ordering checks passed.

For the nominal cosine profile, dt=0.0125 s and 64 rings:

| Fluid | Consumed mass (kg) | Mass / water | Peak wall T (K) | Peak flow (kg/s) | Peak injection pressure (bar) |
| --- | ---: | ---: | ---: | ---: | ---: |
| Hydrogen | 1120.471 | 0.371796 | 1100 | 57.150 | 4.380 |
| Water | 3013.674 | 1.000000 | 1100 | 153.720 | 4.380 |
| Ammonia | 4397.132 | 1.459060 | 1100 | 224.288 | 4.380 |
| Methane | 5189.291 | 1.721916 | 1100 | 264.688 | 4.380 |

The largest adjacent-dt coolant-mass difference over all runs was 0.000934%; the largest 32/64-ring mass difference was 0.003338%. Peak-flow angular-grid sensitivity was larger, at 0.07123%, still inside the chosen gate. These are measured differences, not error bounds or estimates of physical accuracy.

The uniform-control masses reproduce the reported V0 scale (approximately 2334 kg H2 and 6278 kg water). Across uniform/broad/nominal/narrow assumptions, H2 mass spans approximately 2334/1524/1120/727 kg, while ordering stays the same. This large absolute variation is the intended reason to keep the angular distribution explicit.

Only about 13.38% of nonzero-heating steps in this case fall within the implemented radiative correlation's nominal envelope. This is a step fraction, not an energy fraction. It materially limits a physical interpretation of the absolute heat loads even though time/grid convergence passes.

## Interpretation limits

Stable ranking under these tests supports using the current evaluator for a **conditional screening comparison**. It does not establish the correct angular distribution, validity of radiative heating outside its envelope, usable chemistry margin, tank mass or real heat-transfer capability. In particular, fixed trajectory, common wall setpoint and nearly fixed fluid enthalpy windows can make the ranking close to an inverse-enthalpy ordering. Its stability is necessary but not independent evidence of physical superiority.

`chemistry margin` remains unavailable for the fixed-ceiling/default disabled-chemistry cases; the code does not invent a numerical ignition-delay margin. Rarefied heating stays disabled where it was disabled in V0, and skip cases explicitly remain ineligible for this ranking gate.
