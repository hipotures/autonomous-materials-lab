# V4: Ignition-delay constrained hydrogen cooling

## Purpose

V3 showed that replacing the legacy Sutton-Graves / Tauber-Sutton heating
backend with Brandis-Johnston changes absolute coolant mass substantially but
changes the H2/water mass ratio by only order 1e-5.

V4 therefore targets the strongest remaining fluid-specific assumption in the
current evaluator: the maximum usable hydrogen outlet temperature.

The fixed screening ceiling is replaced by:

    tau_ignition(T, P, phi) >= residence_time * safety_factor

where tau_ignition comes from the local Cantera H2/air homogeneous ignition
screen.

This remains a reduced chemistry constraint. It is not a reacting boundary
layer.

## Step 1: generate the lookup table

From experiments/hydrogen-ignition-delay:

    python generate_v4_table.py --workers 16

Default grid:

    T:   600 .. 1100 K in 25 K increments
    P:   0.001, 0.003, 0.01, 0.03, 0.05, 0.1, 0.2,
         0.3, 0.5, 0.75, 1, 1.5, 2, 3, 5, 8, 12, 15, 20, 30 bar
    phi: 2, 4, 8, 16

This is 1680 independent zero-dimensional Cantera cases.

Default chemistry model:

    mechanism: h2o2.yaml
    reactor: adiabatic constant pressure
    ignition marker: maximum sampled dT/dt after >=200 K rise
    integration horizon: 1 s

For no-ignition cases, 1 s is stored as a conservative lower bound on the
delay. The largest default V4 required delay is 0.1 s.

## Interpolation and domain policy

In ignition_csv mode:

- phi must exist explicitly in the table;
- log10(tau) is interpolated in temperature;
- log10(tau) is interpolated in log-pressure;
- pressure is never silently clamped outside the table;
- the maximum safe outlet temperature includes an interpolated threshold
  crossing between temperature grid points;
- if no table temperature satisfies the required delay, the coolant evaluation
  fails instead of inventing a safe temperature.

No interpolation in phi is used.

## Actual coolant state

The chemistry limit is only a ceiling. The actual outlet can be colder because
of the wall-to-fluid approach constraint.

V4 reports:

    minimum_ignition_delay_s
    minimum_ignition_margin
    maximum_coolant_exit_temperature_k

where:

    ignition_margin = tau_actual / tau_required

## Step 2: chemistry sensitivity study

From experiments/entry-evaluator:

    python run_chemistry_sensitivity.py --workers 16 --output-dir chemistry-v4

Default chemistry grid:

    residence time: 0.1, 0.3, 1, 3, 10 ms
    phi:            2, 4, 8, 16
    safety factor:  1, 3, 10

This gives 60 chemistry cases.

The runner reuses the V2 physical Latin-hypercube scenarios and the
Brandis-Johnston heating backend. It now runs the water trajectories first and
uses their active-cooling surface-pressure envelope as a preflight check against
the ignition CSV. If the table does not cover that pressure range or any
requested phi, V4 stops before launching the H2 sweep and writes
`coverage_preflight.json`.

After the coverage gate passes, hydrogen is evaluated for every chemistry case.

Full default study:

    65 physical scenarios
    65 water runs
    65 * 60 H2 runs
    = 3965 trajectories

For a quick nominal-only check:

    python run_chemistry_sensitivity.py --physical-samples 0 --workers 16 --output-dir chemistry-v4-nominal

That runs 61 trajectories.

## Outputs

    chemistry-v4/
      manifest.json
      coverage_preflight.json
      all_runs.csv
      chemistry_comparison.csv
      chemistry_report.json
      runs/

For each chemistry combination the report includes:

- comparable physical scenarios;
- H2-better / water-better / unresolved counts;
- H2/water mass-ratio quantiles;
- ignition-margin quantiles;
- maximum H2 outlet-temperature quantiles;
- non-comparable / chemistry-failure count.

Primary question:

> At what residence-time / equivalence-ratio / safety-factor combinations does
> hydrogen stop beating water?

## Limitations

The lookup models a perfectly homogeneous H2/air parcel. It excludes mixing,
diffusion, atomic oxygen and shock-layer radicals, nonequilibrium chemistry,
wall catalysis, surface reactions and a reacting boundary layer.

A stable H2 advantage under V4 is therefore evidence against one additional
low-fidelity artifact, not proof of flight safety.

## Next stage: V5 liquid / mixture modeling

The project already models known-fluid thermodynamics through CoolProp. What it
does not yet do is create or predict properties for new liquids.

V5 starts the explicit liquid candidate layer:

    composition / molecular descriptor
      -> liquid-state property model
      -> density, cp, h(T,P), phase envelope
      -> viscosity, thermal conductivity
      -> vapor pressure, critical data
      -> chemical compatibility / decomposition constraints
      -> uncertainty
      -> same entry evaluator

The first V5 benchmark should use known binary mixtures and held-out known
liquids so property predictions can be verified before AI proposes hypothetical
molecules.
