# V5e-3: Property-gap active acquisition

V5e-3 selects the next small empirical-reference batch from the existing V5d
exploratory population. It does **not** generate a larger molecular population,
modify the FeOS predictor, update production uncertainty, or promote candidates
to `rankable`.

The trigger for this stage is the audited V5b-3 result. The current completed
run has strict, molecule-grouped reference support for `Tc`, `Pc`, saturation
vapor pressure, vaporization enthalpy and normal boiling temperature, but only
normal boiling temperature has enough calibration/evaluation groups for the
current finite-sample diagnostic. V5e-3 therefore acquires molecules for the
remaining property gaps instead of repeating a generic active-learning batch.

## Objective

The default margin target is:

```text
12 calibration molecule groups
 5 evaluation molecule groups
```

for each priority property:

```text
critical_temperature_k
critical_pressure_pa
vapor_pressure_pa
latent_heat_vaporization_j_kg
```

These targets deliberately exceed the V5b-3 minimum of 9 calibration and 3
evaluation groups. The actual deficits are read from the supplied V5b-3
`summary.json`; the values are not hard-coded from one result.

`liquid_cp_j_kg_k` and `liquid_density_kg_m3` are not acquisition targets in
this version because V5b-3 currently classifies the inherited observations as
pressure/state diagnostics rather than strict benchmark references. V5e-3 does
not manufacture a pressure definition merely to increase the sample count.

## Candidate source

The candidate source is the existing V5d-1 full-prescreen pass population:

```text
../molecular-search-v5d/search-v5d1-results/full_prescreen_results.json
```

By default only the exploratory lane is considered. All molecules from the
previous V5e-1 acquisition batch are excluded before scoring. No new graph
mutation or EOS search is run.

## Two-stage acquisition

V5e-3 separates cheap structural prioritization from empirical-source probing.

### 1. Offline preprobe

Every eligible V5d candidate is scored using only information already available
locally:

```text
V5d property merit
+ current calibration/evaluation deficit for the candidate's deterministic split
+ structural novelty relative to strict anchors for the deficient properties
+ global novelty relative to current strict anchors
```

The split is exactly the V5b-3 split: SHA-256 of the V5b-3 seed plus the
connectivity block of the RDKit-derived InChIKey. A molecule cannot be selected
as an evaluation-gap filler if V5b-3 will deterministically place it in the
calibration split, or vice versa.

The default preprobe shortlist contains at most 120 candidates and applies a
30% per-family cap plus incremental fingerprint diversity.

### 2. Exact identity and source-availability probe

Only the shortlist receives an identity lookup. V5e-3 queries PubChem by exact
InChIKey and caches every HTTP response. It then requires:

```text
candidate full InChIKey == PubChem full InChIKey
formula consistency
molecular-weight consistency
valid CAS candidate
local chemicals metadata full InChIKey match
local chemicals metadata structure full InChIKey match
```

A PubChem synonym or CAS checksum is not enough. If several CAS aliases exist,
only exact local structure matches are considered.

After identity is resolved, V5e-3 probes **availability**, not the reference
value itself. It reuses the audited V5b-3 method allowlist from
`v5b3_audit.py`. A property is marked available only when the local
`chemicals`/`thermo` backend can reproduce an allowed constant, native point or
at least one valid in-range correlation point. Generic estimators rejected by
V5b-3 do not become acquisition evidence here.

For `CRC_HVAP_TB` and `CRC_HVAP_298`, availability is checked through the native
point path. V5e-3 does not call the Watson-shifted legacy grid to make the
reference appear denser.

This stage deliberately does not query NIST WebBook again. V5e-2 already showed
that slow broad network resolution is not the right bottleneck. V5e-3 uses a
short PubChem identity probe and the locally packaged source inventory.

## Greedy property-gap selection

The final batch is selected greedily from identity-resolved probes with local
empirical support. At each step the score combines:

```text
50%  weighted closure of still-open property/split deficits
20%  structural leverage for the still-open properties
20%  V5d thermodynamic property merit
10%  diversity from already selected V5e-3 targets
```

A candidate supporting several deficient properties can close several deficits
at once, but only in its deterministic V5b-3 split. Once a property/split target
is filled, additional candidates no longer receive gap credit for that slot.
The final batch has a 30% per-family cap and a maximum size of 20.

## Conditional projection

`property-gap-projection.json` reports the current counts, configured targets,
selected projected gains and remaining deficits.

The projection is explicitly conditional:

```text
projected_after_if_all_selected_sources_audit_clean
```

An availability probe is not a passed reference audit. The next benchmark must
reconstruct the values, repeat the V5b-3 identity/source/range checks and then
run the fixed predictor. V5e-3 never increments the production calibration set
by itself.

`v5b3-expansion-targets.json` contains identity, selected exact CAS, expected
strict properties and available audited source methods. It contains **no
reference property values**. It is a machine-readable handoff for the next
strict benchmark expansion.

## Runtime and resume

V5e-3 is much lighter than V5e-2. The full V5d pool is processed locally and
only the 120-candidate shortlist normally touches PubChem. Defaults are:

```text
HTTP timeout       8 s
retries            1
minimum interval   0.20 s
```

Every resolved probe is checkpointed. Network responses are cached. An
interrupted run can be resumed without repeating completed probes:

```bash
python run_gap_acquisition.py \
  --output-dir active-learning-v5e3-results \
  --resume
```

Resume is permitted only when the input hashes, config and V5e-3 code signature
match the original run. Changed inputs require a new output directory.

A short smoke test is available:

```bash
python run_gap_acquisition.py \
  --limit-probes 10 \
  --output-dir active-learning-v5e3-smoke-results
```

A limited run is marked `study_complete=false` and must not be used as the final
acquisition set.

## Run

Use the same V5b environment:

```bash
cd experiments/entry-evaluator
source .venv/bin/activate
python -m unittest discover -s tests -p 'test_v5e3.py' -v

cd ../active-learning-v5e
python run_gap_acquisition.py \
  --output-dir active-learning-v5e3-results
```

The default V5b-3 inputs point to the completed post-CAS-fix result directory:

```text
../property-predictor-v5b/property-v5b3-casfix-results/summary.json
../property-predictor-v5b/property-v5b3-casfix-results/audited-reference.json
```

For another result directory, pass explicit paths:

```bash
python run_gap_acquisition.py \
  --v5b3-summary /path/to/summary.json \
  --v5b3-audited-reference /path/to/audited-reference.json \
  --output-dir active-learning-v5e3-results
```

## Interpretation

V5e-3 answers:

> Which already-generated, thermodynamically interesting molecules are most
> likely to close the specific V5b-3 `Tc/Pc/Psat/Hvap` calibration and
> evaluation gaps while remaining structurally useful and supported by an
> auditable empirical source path?

It does not answer whether the new molecules are good coolants. It also does not
claim that source availability equals reference accuracy. The next stage must
reconstruct and audit the selected reference records and rerun the fixed
property benchmark before any applicability or uncertainty model is changed.
