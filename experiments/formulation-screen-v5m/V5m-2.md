# V5m-2: Automatic binary-water predictive grid

V5m-1 was an integration exercise with a handwritten additive list. V5m-2 is a
systematic **parameter-backed computational search**. It discovers water/additive
pairs from the installed ChemSep NRTL table, evaluates a reproducible composition,
temperature and pressure grid with NRTL and Dortmund UNIFAC, and refines selected
regions. It does not fit a new ML model, import HANNA weights, synthesize reference
data, download ThermoML, or claim physical cooling improvements.

## Run

Use the existing project environment. From the repository root:

```bash
git pull --ff-only
cd experiments/entry-evaluator
source .venv/bin/activate
python -m unittest discover -s tests -p 'test_v5m2.py' -v
cd ../formulation-screen-v5m
python run_predictive_grid.py --output-dir predictive-v5m2-results
```

Dependencies are the existing thermo 0.6.1, chemicals 1.5.2, CoolProp 8.0.0 and
RDKit 2026.3.6. The runner does not install or upgrade packages. Full library
source/data trees, versions, configuration and code are fingerprinted.

A three-pair smoke run (separate directory):

```bash
python run_predictive_grid.py --limit-pairs 3 \
  --output-dir predictive-v5m2-smoke-results
```

Inspect the actual automatically discovered catalog without evaluating the grid:

```bash
python run_predictive_grid.py --catalog-only \
  --output-dir predictive-v5m2-catalog-results
```

Resume interrupted work:

```bash
python run_predictive_grid.py --output-dir predictive-v5m2-results --resume
```

Retry failed or timed-out pair workers only:

```bash
python run_predictive_grid.py --output-dir predictive-v5m2-results \
  --resume --retry-failures
```

Changing the code, library contents, configuration or smoke-test limit requires
a new directory. Resuming a finished run reads checkpoints; it does not create
new experiments. `--workers 8` can override the default four workers, but it is
part of the reproducibility signature. Per-pair timeout defaults to 300 seconds.
Each worker logs individual compositions under `workers/*/worker.log`. Failed
workers generate explicit failed records for every requested state. No missing
value is replaced with water or an ideal-mixture prediction. Checkpoint writes
are atomic and hashed; an advisory lock prevents simultaneous writers.

## Search space, not a selected list of additives

The catalog consists of water pairs actually present in the installed
`thermo.interaction_parameters.IPDB.tables['ChemSep NRTL']`. NRTL requires both
directed `bij` and `alphaij` entries. Missing entries do not become the database's
default zero interaction. The file records the water-first parameter order and
`tau_ij = bij/T` convention.

Each compound is checked against local CAS/SMILES/full-InChIKey metadata.
Dortmund uses packaged group assignments and `DOUFIP2016`; every directed
interaction between distinct main groups must exist. The library's missing-
interaction defaults are never silently accepted. Duplicate identities are
removed. Single-model pairs remain in the catalog and raw predictions, but
cannot qualify for two-model tradeoff selection.

The default domain is neutral, nonradical, single-component organic C/H/O
additives up to 250 g/mol, with tabulated pure melting/boiling temperatures
bracketing the 293.15 K inlet. Carboxylic acids, peroxides, anhydrides and
three-membered oxygen rings are excluded by explicit SMARTS as initial model
scope guards. This intentionally excludes electrolytes, acid/base speciation,
solid dissolution, gases stored under pressure, suspensions and emulsions.
It is not a solubility model or an assessment of chemical handling safety.

No additive is included because its name was suggested in chat. However, this
is **not an exhaustive universe of commercially available chemicals**: the
catalog is biased by the installed parameter database and the declared domain.
Known identity does not verify procurement, purity, availability or safe handling.
All candidates retain `commercial_availability_verified=false` and an unreviewed
handling status. Rejected entries and reasons are written to a separate table.
There is no default pair budget; an optional configured budget is reported.

## Grid and adaptation

The default additive **mass-fraction** coordinate has 24 unique points:

- Nine logarithmically spaced points from 0.0001 to 0.01.
- Sixteen linearly spaced points from 0.01 to 0.30, sharing the transition point.

Thus the domain is 0.01 to 30 mass %, with water exactly `1-w`. These are search
bounds, not recommended recipes or an assertion that all mixtures are stable.
The inlet is 293.15 K, outlets 350/400/450 K, pressures 101325/200000 Pa. There
are 288 requested coarse states per discovered pair: 24 x 3 x 2 x 2 models.
Every pair receives the same grid, including failed conditions.

After the coarse grid, up to 12 pairs receive up to six extra composition
midpoints around non-dominated regions and large model discrepancies. Half of
the pair budget is reserved for disagreement exploration where available.
`refinement-diagnostics.csv` reports changes in the best sampled enthalpy ratio.
One refinement is **not** a convergence proof; no global optimum is claimed.

## Models and guards

Both branches use thermo's GibbsExcessLiquid with `equilibrium_basis='Psat'`
and `caloric_basis='Psat'`, an ideal-gas vapor, and FlashVLN allowing up to two
liquid phases. The NRTL parameter set is ChemSep, not the V5a demonstration fit.
The second branch uses modified UNIFAC Dortmund 2016 group parameters. The models
share pure-component correlations and are not statistically independent.

The fixed pure correlations are chosen deterministically by declared grid-range
coverage, then library priority. Their methods and bounds are recorded. Their
extrapolation is disabled. Requested states and the common ideal-gas enthalpy
reference at 298.15 K must be within declared bounds. Missing bounds, unsupported
supercritical component states and failures are recorded, not extrapolated away.
The allowed pressure range 25..300 kPa is an operational limit of this ideal-vapor
screen, not proof of physical accuracy. Activity-model fit ranges are unknown and
remain null. No temperature derivative or excess enthalpy is called validated
merely because the activity model has fitted VLE parameters.

Each flash must close component and phase balances. Inlet vapor or two inlet
liquids fail the single-liquid formulation gate; two outlet liquids are also
excluded from ranking. Outlet vapor and a single-liquid/vapor state are allowed.
Phase compositions, molar vapor fractions and vapor additive **mass fractions**
are recorded separately. Two-phase Cp is null. These are equilibrium states at
fixed overall composition, **not** a transient evaporating pore or reservoir.
Melting depression, reaction, decomposition and salt precipitation are not modeled.

## What the tradeoffs mean

The main caloric result is `h(outlet,z)-h(inlet,z)` using the same backend and
composition for both enthalpies. Each binary backend is also evaluated at its
own zero-additive water endpoint. A separate HEOS water calculation checks that
endpoint; errors above the configured 5% block two-model comparison. The 5% is an
operational comparator threshold, not a measured model uncertainty.

The output contains both HEOS-relative and same-model-water-relative enthalpy
ratios. Same-model comparison exposes additive trends without silently claiming
that cancellation removes physical model bias. The predicted equal-net-heat
mass ratio is the inverse enthalpy ratio. Any needed extra reduction of incoming
heat to compensate an enthalpy penalty is a **break-even requirement**, not an
achieved wetting or protective-vapor-layer effect.

Liquid volumes use additive pure molar volumes. The viscosity ratio is an
explicit molar-log-mixing **proxy**, calculated only when both pure viscosities
have bounded correlations at the inlet. It is not a mixture-specific measured
correlation. Surface tension, contact angle, fouling and dryout predictions are
not invented. Hydraulic model accuracy is not established by the proxy.

Only formulations with eligible results from **both models at all configured
conditions** enter the main tradeoff tables. Incomplete grids remain in raw
results. A formulation cannot improve its score by failing difficult conditions.
Two Pareto sets are produced without an arbitrary weighted total score:

1. Maximize the worst sampled same-model-water enthalpy ratio, minimize the
   maximum storage bubble-pressure ratio.
2. The same objectives plus the maximum viscosity-ratio proxy. Rows missing that
   proxy do not enter this second set; they remain in the first set when eligible.

These objectives describe thermodynamic and delivery-pressure tradeoffs, not a
complete TPS objective. A separate two-model spread quantifies disagreement;
it is **not a calibrated uncertainty interval**. The validation shortlist has
separate tradeoff and disagreement roles and is not an approved physical-test
list. No global ranking of handling safety or flight performance is produced.

## Optional external-data validation

`validate_predictive_grid.py` provides a fixed-model comparison interface for
source-linked measurements of bubble pressure and molar excess enthalpy. It does
not run by default because no such measurement file is supplied with this stage.
There are no synthetic example measurements in production outputs.

```bash
python validate_predictive_grid.py --references measured-mixtures.json \
  --output-dir validation-v5m2-results
```

Input is a normalized JSON object with `schema: binary-mixture-measurements-v1`
and an `observations` array. Each observation requires `id`, `source` (DOI or
traceable record), `evidence_kind: measured`, `water_cas: 7732-18-5`,
`additive_cas`, `composition_basis: liquid_mole`, `liquid_additive_mole_fraction`,
`phase: homogeneous_liquid`, `temperature_k`, `pressure_pa`, `property`, `unit`
and `value`; optional `standard_uncertainty` is retained. Supported property/unit
pairs are `bubble_pressure_pa`/`Pa` and `excess_enthalpy_j_mol`/`J/mol`.
Bubble pressure must agree with the stated measurement pressure. Negative excess
enthalpies are valid, and relative error at zero excess enthalpy remains null.

References are frozen before comparison; errors are grouped by additive/pair,
property and model. Failed predictions remain counted. There is no parameter
refit, random row split, claimed blind holdout, or formal coverage guarantee:
training overlap with ChemSep/UNIFAC is unknown. This tool assumes normalized,
reviewed inputs; it is not an automatic ThermoML downloader or universal parser.
The absence of external data is explicitly reported, not filled with model output.

## Output files

- `catalog.json`, `catalog.csv`, `catalog-rejections.csv`: discovered scope.
- `grid-plan.json`, `refinement-plan.json`: reproducible requested states.
- `prediction-grid.csv`, `predictions.json`: results, phases and model provenance.
- `coarse-tradeoffs.csv`, `tradeoffs.csv`: complete/incomplete paired comparisons.
- `pareto-thermodynamic.csv`, `pareto-with-flow-proxy.csv`: explicit tradeoffs.
- `refinement-diagnostics.csv`, `validation-shortlist.csv`: next verification targets.
- `summary.json`, `manifest.json`, `artifact-hashes.json`, `progress.json`.
- `checkpoints/`, `workers/`: restart state, worker requests and numerical logs.

A catalog-only or limited-pair run is marked incomplete as a full experiment.
`study_complete` means the requested full catalog run was processed, not that
models were validated. Read state counts and `complete_two_model_formulation_count`.
A zero count is reported as `no_complete_two_model_comparisons`, not a discovery.
Worker and model-initialization failures cause exit code 1. All prior molecular
and V5m-1 artifacts are left unchanged. No entry uncertainty or production
rankability flag is updated.

## Tests

`test_v5m2.py` exercises directional-parameter gates, identity misses, composition
and phase balances, units, bounds, endpoint mismatch, failed-state selection,
Pareto logic, refinement, checkpoints, worker timeout and external-data contracts.
Four integration tests require the real pinned thermo/chemicals/CoolProp stack;
missing libraries cause explicit skips, never a reported numerical success.
