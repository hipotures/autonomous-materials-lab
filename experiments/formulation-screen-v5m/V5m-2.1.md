# V5m-2.1: Water-aware review and compressed publication

This is an offline reanalysis of the already computed V5m-2 grid. It does not
recalculate thermodynamics, change the original predictor, train ML, collect
measurements, or authorize a physical experiment. Original results and their
manifest remain unchanged. No change to the original run signature is required.

## Run on the completed experiment

From `experiments/formulation-screen-v5m`, after pulling the new code:

```bash
git pull --ff-only
python -m unittest discover -s ../entry-evaluator/tests -p 'test_v5m21.py' -v
python review_predictive_grid.py \
  --input-dir predictive-v5m2-results \
  --output-dir review-v5m21-results
```

Only the Python standard library and the existing dependency-free `v5m2_core.py`
are used. No CoolProp, thermo, FeOS, RDKit, network or sensor calls are made.
Input must be a completed full V5m-2 run, with the original manifest, artifact
hashes, catalog, grid/refinement plans, prediction CSV and summary. Optional
published source reports are archived when present. Missing scientific state
rows do not disappear from a denominator: the review rejects an incomplete grid.
Model failures recorded by the original runner remain explicit and are retained.

Use a separate output directory. The command refuses an existing output rather
than overwriting a published review. There is no costly solver work to resume.
Output is staged atomically; interruption does not publish a complete summary.
The original `.run.lock`, when present, is checked without modifying it. Source
hashes are verified both before and after review to detect concurrent edits.
A clone of the 16 published reports is sufficient; checkpoints are not needed.

## Compression contract

At the end of the review, original allowlisted scientific CSV/JSON files are
streamed into `archive-<original-name>.gz`. Every decompressed byte is checked
against the source SHA-256. Original line endings and whitespace are preserved.
The writer omits the original path and creation time from the gzip header.
Compressed bytes are reproducible with the same gzip/zlib implementation; the
uncompressed SHA-256 is the cross-runtime content identity.

Derived tables are compressed as `table-<label>.csv.gz`. Small summary/manifest
JSON files stay readable and also have gzip copies. Publication indexes and
hash lists remain plain text. No source file is deleted, rewritten or silently
replaced with a compressed version. The old run's `artifact-hashes.json` is not
rewritten. Already committed large files remain in Git history; this step does
not perform a history rewrite or garbage collection.

**Gzip is not a promise of connector compatibility.** A text-only connector may
not decode binary archives. To support it, the same command publishes bounded
UTF-8 report shards (`report-*.csv`), normally at most 48 KiB each. Every pair
and all paired compositions/conditions are represented, not just favorable
points. `publication-index.json` identifies reports, row counts, sizes and hashes.
All detailed source values remain in the verified archives. No synthetic rows
are included as measurements; the water row is a normalization identity.

To read an archive locally with Python:

```python
import gzip
import csv
with gzip.open('review-v5m21-results/archive-prediction-grid.csv.gz',
               'rt', encoding='utf-8', newline='') as stream:
    reader = csv.DictReader(stream)
    first = next(reader)
    print(first['status'])
```

## Scientific reanalysis

1. Check the original source artifact hashes, the manifest contract, identities
   linking rows to the catalog, and every planned model/composition/T/P key.
2. Recompute the original complete-grid comparisons from the CSV and verify the
   eligible-formulation count against the source summary.
3. Add pure water explicitly to both descriptive Pareto sets with enthalpy,
   bubble-pressure and viscosity ratios equal to one. These are normalization
   identities, not a new measurement or an additional model prediction.
4. Separate results by outlet temperature and pressure, retaining each model
   and incomplete paired comparisons. Report whether a local paired gain exists
   even when the global worst-case criterion has no gain.
5. For the largest model discrepancy per pair and T/P, show both ratios at the
   **same composition**, plus exported outlet vapor fractions, liquid-phase counts
   and inlet excess enthalpies. Missing exported quantities remain null.
6. Report required net-heat reduction `max(0, 1-r)` and equal-net-heat mass ratio
   `1/r`. These are balance-derived requirements, not an achieved surface effect.

The default gain-reporting margin is 0.001 (0.1%). Counts above zero and above
this margin are both reported. The margin is a sensitivity label, **not** an
empirical error bar, significance level, physical acceptance threshold or a
change to exact Pareto dominance. Override with `--gain-margin`, recording it
in the new manifest. Tiny differences remain visible without being called
statistically meaningful. This retrospective review does not produce an
independent validation dataset by selecting favorable temperatures afterward.

The pressure objective remains descriptive: minimizing storage bubble pressure
is not automatically a benefit to the apparatus. No arbitrary pump limit is
invented. The optional flow Pareto still uses V5m-2's unvalidated viscosity
mixing proxy. Neither that proxy nor model agreement is calibrated uncertainty.
No surface-tension, wetting, fouling, phase-accuracy or pore-flow gain is inferred.

## Read first

- `summary.json`: global and per-T/P counts, water dominance and archive sizes.
- `report-regime-summary-*`: best paired composition and coverage per pair/T/P.
- `report-model-regimes-*`: separate-model results, including recorded failures.
- `report-disagreements-*`: matched-composition model/phase discrepancies.
- `report-pareto-water-*`: descriptive Pareto sets with the water control.
- `report-pair-*`: all paired compositions and conditions, split into small files.
- `publication-index.json`: complete report/archive index and checksums.

## Publish

From the same experiment directory:

```bash
git add -- review-v5m21-results/
git diff --cached --stat -- review-v5m21-results/
git commit --only -m "Add V5m-2.1 water-aware review and compressed results" \
  -- review-v5m21-results/
git push origin HEAD
```

Review staged paths before committing. Local ignore rules admit only the named
archives and report families; temporary build trees, logs and unrelated outputs
remain ignored. Do not use a forced add or `git clean -fdx`.

## What follows

Use these results to determine whether the no-gain result is global or also
holds in individual regimes. For a genuine local model hypothesis, validate the
relevant phase equilibrium and caloric properties before further optimization.
If the caloric result instead converges toward pure water throughout the useful
regimes, investigate water-enhancement mechanisms through a separately defined
surface/flow model or matched physical measurements. Do not train an ML model
on these same predictions and call it independent confirmation.

The original V5m-2 runner is deliberately not modified: invoking its old
`--resume` still has the original computation contract. This new finalization
command handles compression and review for completed runs without rerunning or
invalidating their checkpoints. Future experiment runners can use the same
lossless publication helpers at their own finalization stage.
