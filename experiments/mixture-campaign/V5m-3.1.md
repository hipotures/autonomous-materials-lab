# V5m-3.1: Shared reference controls and evidence-aware adaptation

## Purpose

Extend the reusable mixture campaign, not create another compound-specific run.
Every accepted water/additive pair receives the same baseline and six required
studies. The existing ChemSep NRTL and Dortmund UNIFAC mixture physics remains
unchanged. This revision does not recalibrate the caloric model, add empirical
measurements, train ML, certify cooling performance or promote a mixture.

The motivating V5m-3 run is `run-20260909T220017Z-58a3f01e`, published in commit
`00aad2242a652131148699bff0308b2de23471e4`. Its common baseline used 144 coordinates
per pair and its adaptive stage reached 180 additional coordinates per pair.
The revision addresses how the engine diagnoses and routes unresolved work.

## Run and migrate

From the repository root:

```bash
git pull --ff-only
cd experiments/entry-evaluator
source .venv/bin/activate
python -m unittest discover -s tests -p 'test_campaign*.py' -v
cd ../mixture-campaign
python run_campaign.py
```

The default result root stays `campaign-v5m3-results`; the summary now declares
`study_version: v5m-3.1`. Do not remove `.campaign-cache`. Old published snapshots
are read for history/diffs, never overwritten or treated as automatically trusted
numerical cache entries. Matching local V5m-3 `model.freeze` and `model.state`
entries are reused. New adaptive requests may differ and require new states.

The legacy backend files and `campaign_store.py` have not changed in this
revision. Their signatures, rather than an informal version label, determine
mixture cache reuse. Updating an installed numerical library can still invalidate
states conservatively. Observation bundles and dependent analyses are rebuilt
under the new quality contract. New pure-water controls have separate task keys.

For a custom YAML copied from V5m-3, retain the original four studies and append
`water_reference_audit` and `evidence_needs` to `studies`. The new optional policy
sections have validated defaults. The default YAML already contains all changes.

## Shared pure-water control

`campaign_water.py` adds an isolated numerical worker without changing the legacy
mixture worker. A water context projects the actual selected water correlations,
selection-temperature envelope, inlet temperature, caloric/equilibrium bases,
ideal-gas assumption and reference provider. Its task signature also contains
the numerical implementation and the same complete library/environment identity.
It does not contain additive identity or activity-model identity: these are not
inputs to the thermodynamic pure-water limit.

For each distinct context, the worker constructs pure-water `GibbsExcessLiquid`
with `equilibrium_basis="Psat"` and `caloric_basis="Psat"`, an `IdealGas`, and a
`FlashPureVLS`. It uses the exact same correlation-selection function as the
legacy binary backend and verifies the selected metadata before calculation.
It then compares the same-composition inlet/outlet enthalpy difference against
CoolProp HEOS Water. This is a reference-model comparison, not a new measurement.

Default control sampling is 21 temperatures by 5 logarithmically spaced pressures
across the declared scope, including any extra coarse-axis values. Every exact
T/P used by a mixture observation or reference comparison is also controlled.
The initial map is diagnostic sampling, not a certified continuous validity map.
One shared service deduplicates controls across models and pairs, including
parallel pair execution and forced recomputation within one invocation.

The control records contain selected correlation metadata, exact conditions,
phase checks, saturation pressures, model/HEOS delta-h and its relative error.
Additional latent-heat and liquid-Cp diagnostics retain their comparison basis.
In particular, the Cp diagnostic compares the model liquid at the requested
pressure against HEOS saturated-liquid Cp; it must not be interpreted as an
independent matched-pressure Cp validation. Optional diagnostic failures are
reported without erasing a successful primary enthalpy control.

At a T/P point too close to either saturation curve, the worker records ambiguity
instead of choosing an arbitrary pure-water quality. Phase mismatch or unavailable
controls block mixture comparison. The existing endpoint tolerance remains 0.05;
it is not widened to admit an attractive result.

### Checking the sharing assumption

Each otherwise successful binary result must reproduce both the shared control's
model-water denominator and its HEOS denominator within the configured consistency
tolerance, default `1e-7` relative and `1e-6 J/kg` absolute. A discrepancy becomes
`water_control_context_mismatch`; it is not silently corrected. This guards the
pure-limit equivalence against implementation differences and incorrect reuse.

Raw cached solver results are never mutated. Annotated observation bundles retain
`raw_model_comparison_eligible`, `comparison_blockers`, `water_context_id` and the
control task reference. The effective eligibility is the original eligibility
AND a passing shared control and consistency check. A new audit can block a
comparison; it cannot promote a previously ineligible raw result.

## Evidence-aware refinement

The planner separates four kinds of sampled edges:

| Edge class | Action |
| --- | --- |
| Refinable | Compute a midpoint, respecting scientific priority and axis balance |
| Resolved at configured resolution | Retain the bracket and resolution basis; no further midpoint required |
| Reference-blocked | Record the water issue and create a shared reference-model review need |
| Evidence-limited disagreement | Request external evidence rather than repeatedly sampling the same stable discrepancy |

A model discrepancy is evidence-limited only when both eligible endpoints exceed
the model-spread trigger, remain in the same sampled phase/feasibility regime,
have sufficiently stable spread and are already within a local resolution.
Defaults are additive mass-fraction span 0.01, temperature span 5 K,
`ln(P_right/P_left)` span 0.08 and spread-change tolerance 0.01. These are numerical
work-allocation rules, not calibrated uncertainty or accuracy tolerances.

An independent phase transition, paired-gain boundary or significant gain-region
gradient is still refinable. A water-reference block suppresses enthalpy-gain
reasoning, not independently observable mixture phase transitions. Neither water
agreement nor two-model agreement proves mixture accuracy.

`adaptive_stop_reason` is the primary cause; `adaptive_stop_causes` retains all
simultaneous constraints. Possible normal reasons include:

- `point_budget` or `max_rounds`: useful numerical work remains;
- `reference_blocked`: the reference contract blocks interpretation;
- `model_disagreement_requires_evidence`: local model disagreement remains;
- `sampled_boundaries_resolved` or `no_triggered_sampled_edges`: no more work is
  required by the configured sampled-edge rules.

A planner failure remains an incomplete run. All reports keep
`continuum_convergence_claimed: false`. None of these statuses proves absence of
unsampled islands, locates an exact binodal or identifies a global optimum.

## Machine-readable evidence acquisition needs

The `evidence_needs` study creates deterministic requests with property, units,
component identities, composition basis, exact conditions, priority, acquisition
route and provenance fields. Water-model review requests are shared across
consuming pairs. Pair-specific caloric and phase requests remain distinct.

The mixture request budget defaults to eight representative points per pair.
Selection includes the best eligible paired gain, persistent disagreement,
representative domain coverage and unresolved phase transitions. A high raw gain
blocked by water quality may generate a diagnostic-only validation request, never
a winner. Unselected point counts and queue-budget limits remain explicit; this
is not a claim that eight points cover every missing physical property.

Current routes and statuses are:

| Route | Implemented behavior |
| --- | --- |
| `reference_backend_review` | Emit a model/context diagnosis with its shared control identity |
| `normalized_local_measurements` | Match supplied source-declared measured delta-h records at the same composition, inlet, outlet and pressure |
| `phase_measurement_adapter_required` | Explicitly request a phase-data adapter; do not reinterpret unrelated properties as phase evidence |
| `physical_measurements_required` | Require a hardware protocol and matched cooling/transport measurements |

A matching measured delta-h record is marked
`source_linked_measurement_available_not_certified`. Its original source, value
and uncertainty are retained. `satisfied` remains false because source
independence, training overlap and accuracy acceptance are not established by an
identifier match. A different inlet temperature does not close the request.
Missing references remain null; predictions are never copied into reference
fields. This revision does not implement online literature downloading or claim
that a physical test was run. The queue is the explicit interface for subsequent
acquisition modules and experimental ingestion.

## Publication and failure semantics

Additional compressed dossiers:

```text
water-controls.json.gz
evidence-needs.json.gz
```

Additional bounded text report families, plus compressed complete CSV tables:

```text
report-water-controls-*.csv
report-evidence-needs-*.csv
report-evidence-consumers-*.csv
report-evidence-sources-*.csv
```

Consumers are published separately so that a widely shared request does not
create an unbounded CSV row. Gzip and file hashes use the existing verified
publication machinery. New filenames are explicitly admitted by `.gitignore`;
workers, raw cache, partial output and logs remain local. Full source evidence
also remains in the compressed request dossier.

The scientific snapshot includes shared-control and evidence-queue hashes.
Summary counters distinguish water task failures, blocked controls, blocked
mixture points, unique evidence requests, consumer links and simultaneous stop
causes. Water worker failures count as numerical task failures. An unavailable
or inaccurate reference result is recorded separately from a crashed worker.
Corrupt control-cache objects are fatal integrity errors, not scientific gaps.

Use the same `python run_campaign.py` after changing data, a study or a policy.
`--retry-failures` retries stored task failures. `--recompute` also re-executes
completed tasks. Neither deletes old attempts or snapshots. A future correction
to the actual mixture physics must change that backend's signature and rerun its
dependent states; this diagnostic revision deliberately does not conceal such a
correction in the reporting layer.

## Tests and primary implementation references

`test_campaign_quality.py` adds synthetic tests for shared contexts, concurrent
single-flight controls, pure-reference blocks, unchanged raw cache, mismatch
guards, failed workers, corrupt-cache propagation, evidence-limited adaptation,
exact-condition source matching, immutable snapshots and incremental reuse.
The legacy campaign tests still run. Two new optional real-stack integration
tests compare the standalone pure-water limit with both binary models and test
the isolated water worker in the pinned project environment.

These tests validate implementation behavior; synthetic fixtures are never used
as thermodynamic calibration or physical evidence.

Primary API references used for the pure-water adapter:

- Thermo FlashPureVLS: https://thermo.readthedocs.io/thermo.flash.html
- GibbsExcessLiquid implementation, including the default IdealSolution and
  explicit caloric basis: https://thermo.readthedocs.io/_modules/thermo/phases/gibbs_excess.html
- Thermo phase/flash interfaces: https://thermo.readthedocs.io/tutorial_phases_and_flash.html
