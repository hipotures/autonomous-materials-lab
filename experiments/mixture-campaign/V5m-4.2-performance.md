# V5m-4.2 execution tuning

This revision changes execution scheduling only. It does **not** change the
mission, thermodynamic models, composition grid, scoring equations, evidence
rules, or cache ABI.

## Why

V5m-4.1 used four pair-level workers and only four compositions per numerical
subprocess. A normal 40-composition pair plus its zero-limit control therefore
reloaded Python and rebuilt the same mixture model repeatedly. In addition,
50-pair checkpoint batches created frequent synchronization and publication
barriers.

## Default execution

Always launch the mission campaign through:

```bash
python run_campaign.py
```

The public runner now chooses a worker count from Linux CPU affinity and
available memory. It reserves CPU headroom, limits the automatic choice to 32
workers, and assumes 768 MiB of available memory per worker when applying the
memory guard. The decision is printed as `[runtime-tuning] ...` before the
campaign starts.

Explicit CLI choices are never replaced:

```bash
python run_campaign.py --workers 24 --batch-pairs 384
```

Environment overrides are also supported:

```bash
AML_WORKERS=48 AML_BATCH_PAIRS=768 python run_campaign.py
```

The automatic ceiling can be changed without editing the repository:

```bash
AML_MAX_WORKERS=48 python run_campaign.py
```

`AML_WORKER_MEMORY_MIB` changes only the scheduling heuristic. These variables
must be positive integers.

## Fewer process startups

`execution.batch_compositions` is now 64. The standard 40 positive composition
points plus the zero-additive control therefore fit in one `states` subprocess
per pair/model rather than eleven calls of four compositions. Historical extra
compositions may require an additional call. Numerical cache keys do not contain
this batching choice, so compatible state results remain reusable.

The default checkpoint batch is 512 pairs when no runtime override is injected.
With automatic tuning it is `16 * workers`, bounded to 50..1024 pairs. The batch
controls checkpoint/publication cadence; it does not change which pairs belong
to the scientific catalog.

## After the completed full-catalog run

Do **not** rerun all 6009 pairs with `--recompute` merely to use faster
scheduling. To revisit the numerical failures recorded by V5m-4.1, use:

```bash
python run_campaign.py --retry-failures
```

Successful compatible state tasks remain cache hits. Pairs whose dossiers
contain failed tasks are reopened and only missing/failed numerical dependencies
are retried under the existing cache rules.

## Interpretation

More CPU utilization is not scientific evidence. Runtime worker counts,
subprocess batching, and checkpoint cadence are execution parameters and remain
outside scientific cache signatures. A result produced with different execution
settings is expected to have identical scientific content when all underlying
numerical tasks succeed.
