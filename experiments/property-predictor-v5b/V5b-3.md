# V5b-3: Audited reference-property benchmark

V5b-3 audits existing V5e-2.1 property packets, freezes the accepted reference
records, and evaluates the unchanged structure-derived FeOS predictor. It does
not rerun PubChem/NIST requests, expand the molecular search, refit GC-PC-SAFT,
change V5b-2 uncertainty artifacts, or promote any molecule to `rankable`.

This is an audit and benchmark experiment, not evidence that the newly selected
molecules or their reference data are accurate. In particular, the old `high`
and `executable` flags are not acceptance evidence and are not used as gates.
All input targets, including `partial` packets, are considered property by property.

## Run

Use the existing Linux V5b virtual environment. The predictor retains the
repository's exact dependency checks: FeOS 0.10.1 and RDKit 2026.3.6. Reference
reproduction uses chemicals 1.5.2 and thermo 0.6.1. No dependencies are upgraded
by this experiment.

From the repository root:

```bash
git pull --ff-only
cd experiments/entry-evaluator
source .venv/bin/activate
python -m unittest discover -s tests -p 'test_v5b3.py' -v
cd ../property-predictor-v5b
python run_v5b3.py --output-dir property-v5b3-results
```

The default input is already produced by the previous experiment:

```text
../active-learning-v5e/reference-v5e21-results/empirical-reference-properties.json
```

Custom input:

```bash
python run_v5b3.py --input /absolute/path/empirical-reference-properties.json \
  --output-dir property-v5b3-custom-results
```

An audit without predictor execution:

```bash
python run_v5b3.py --audit-only --output-dir property-v5b3-audit-results
```

Resume an interrupted run without repeating completed molecules:

```bash
python run_v5b3.py --resume --output-dir property-v5b3-results
```

Retry only cached prediction failures, including timed-out molecules:

```bash
python run_v5b3.py --resume --retry-failures --output-dir property-v5b3-results
```

Resume requires the same input bytes, configuration, code, parameters, package
versions and reference-library files. Changed inputs require a new output directory.
A full benchmark can follow an audit-only run using `--resume` when the runtime
is unchanged. An audit-only run cannot overwrite a completed full benchmark.
The runner uses a Linux advisory lock to prevent concurrent writers.

## Reference audit

1. Recompute full InChIKey and formula from the target SMILES using RDKit.
2. Resolve the selected CAS from the packaged chemicals metadata and require the
   same CAS, full InChIKey, structural InChIKey, formula and consistent molar mass.
   A checksum or a PubChem synonym alone is not sufficient. Metadata derived from
   PubChem is not counted as independent experimental evidence. Unresolved CAS
   records are quarantined rather than replaced with whichever alias has more data.
3. Ignore the old quality score. Use a property-specific, explicit method allowlist.
   Unknown methods, PD compilation entries not reviewed for this audit, and the
   old direct NIST parser output are excluded. Excluded records remain in the audit.
4. Reproduce the selected constant or correlation from the installed local data.
   A mismatch greater than 0.01% is quarantined, not silently overwritten.
5. For critical constants and boiling temperature, compare other allowed local
   compilations. Cross-compilation discrepancies exceeding 10% are quarantined.
   This check does not prove independence or accuracy. The old packet lacks the
   alternate dynamic-source records, so cross-source dynamic consistency is not
   claimed by this experiment.
6. Enforce both declared library bounds and method validity. No temperature
   extrapolation is accepted. Declared library bounds are not a measured error bar.
7. Collapse every Poling method to `POLING`. Source-group counts describe provenance
   labels only, not independent measurements. Primary measurement identifiers and
   measurement uncertainties remain null where the input does not establish them.

### Recover native points, not estimator-generated curves

`CRC_HVAP_TB` and `CRC_HVAP_298` are read directly from the underlying tabulated
attributes at their native reference temperature. The legacy temperature grid is
replaced by that single point. The Watson temperature correction is not called.
`POLING_CONST` and `CRCSTD` liquid heat capacities are retained only at 298.15 K.
A repeated constant is never turned into several independent temperature samples.
The recovery is logged with the original record hash and the number of replaced
legacy grid points. A missing native record fails closed.

### Match the physical property

Strict comparisons cover `Tc`, `Pc`, normal `Tb` at 101325 Pa, vapor pressure at
specified temperature, and vaporization enthalpy on the saturation curve. VDI
liquid tabulations explicitly identified as saturation data are compared with the
predicted saturated liquid state.

Other inherited liquid-density and liquid-heat-capacity packets do not preserve
sufficient pressure information. They are retained as **diagnostics at predicted
saturation**, with `benchmark_eligible=false`. They cannot calibrate uncertainty.
That also avoids silently equating saturation-path heat capacity with isobaric Cp.
No pressure correction or new liquid-storage model is invented to repair them.
The experiment does not validate melting, decomposition, reactivity or transport.

## Prediction isolation and numerical failures

The worker receives only SMILES and value-free observation requests: property,
temperature, pressure and state definition. It receives neither CAS identifiers
nor source methods, reference values, reference critical points or fitted parameters.
Reference measurement temperatures are permissible state controls, not model inputs.
The reference JSON is frozen before any worker starts. Predictions are persisted
before comparison, and the worker never imports chemicals or thermo.

The adapter reuses `FeosGcPcSaftProvider` and its pinned parameter files. Critical
point initial guesses are fixed independently of reference data. Saturated density,
Cp and vaporization enthalpy are taken from a genuine FeOS liquid-vapor equilibrium,
not arbitrary pressure offsets. Negative/nonfinite values, degenerate equilibria,
solver errors and timeouts are recorded separately from successful comparisons.

Each molecule runs in a separate process with a 90-second wall-clock timeout.
Progress is printed at audit and prediction stages. Checkpoints are atomic and
content-hashed. A timeout does not block subsequent molecules. A fatal dependency
or schema problem stops before it can masquerade as a completed valid benchmark.

## Statistical contract

The split is a deterministic hash of the InChIKey connectivity block, with a fixed
seed and nominal 30% evaluation fraction. Aliases, stereoisomers with the same
connectivity, and all temperatures of a molecule stay in the same group. The split
is not rebalanced based on prediction success or error. Exact duplicate observations
are deduplicated. Scores are reported per molecule and property; a molecule with
more grid points does not receive more statistical weight.

The error-envelope diagnostic uses the maximum absolute relative error per
calibration molecule and order statistic `ceil((n + 1) * coverage_target)`. If this
index exceeds `n`, calibration has too few molecules or has incomplete predictions,
no finite envelope is emitted. There is no fallback that claims unsupported 90%
coverage. Evaluation failures count as uncovered in the coverage denominator.

Default minimums are nine complete calibration groups and three evaluation groups
per property. With the present small acquisition set, many properties may correctly
report insufficient data. Raw per-property errors are still useful. The actively
selected dataset is not assumed exchangeable with deployment molecules, and no
formal coverage guarantee is claimed. These diagnostics do not update production
uncertainty or the entry-mass uncertainty model.

Structural similarity is computed for evaluation molecules against successful
calibration groups for the same property only. Self/connectivity matches are
excluded. `structural_support_only` is not a calibrated applicability-domain flag.

The manifest fingerprints input, code, parameter files, Python, packages and the
packaged reference-library source/data files. It does not modify earlier run outputs.
All JSON outputs disallow NaN/Infinity. Missing quantities are null with explicit status.

`study_complete=true` means the requested full run finished processing its inputs;
it is not scientific acceptance. Read `run_status`, `benchmark_has_comparable_results`,
`strict_failed_prediction_count` and the per-property results. The experiment always
reports `rankable_promotions=0`, `predictor_parameters_changed=false`, and
`entry_uncertainty_updated=false`.

## Tests and limits

`test_v5b3.py` covers identity rejection, native-point recovery, source grouping,
method/range/unit gates, prediction-input isolation, timeout handling, grouped
statistics, corruption detection and end-to-end checkpoint/resume behavior. Two
integration tests exercise actual chemicals/thermo data and the existing FeOS
provider when those packages are installed. Mocked numerical tests are not a
substitute for these integration tests or for the 50-target experiment.

The first result to inspect is the audited per-property comparison, not a new
coolant ranking. A subsequent model change needs its own preregistered calibration
and evaluation protocol. Existing V5b-2 CoolProp entry holdouts remain unchanged.
